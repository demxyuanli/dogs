1. 这是什么工程

Open CASCADE Technology（OCCT）是开源三维 CAD 几何内核：实体建模、布尔运算、圆角抽壳、 STEP/IGES 交换、三角网格等。dogs 的目标是用 Rust 按 OCCT 控制流逐步搬迁， 而不是另写一套「看起来差不多」的几何库。

标准答案
OCCT 8.0.0 源码行为
缺分支就标注文件:行号，禁止用启发式凑某一模型的数字
验收方式
对拍既有基线
网格 v/f、体积、拓扑；不为对齐新写测试
这套环解释了为何文档强调「对拍」而不是「测试通过率」。

5. 「未满 100%」该怎么读

不要把类覆盖率当成完成度百分比 统计口径是「OCCT 类型全名是否出现在 Rust 文本里」。宏头、句柄别名、仅调试编译存在的打印模块也会进分母； Rust 用 const / Arc / 日志惯用法表达同一语义，不必再造同名空类。
波次表上数字白话缺口要不要补空壳
S2157/174 · 777 行宏 / 句柄别名 / 调试死码否
S2i38/40typedef / 枚举命名差异否
S3122/129 · 136 行7 个薄转发外壳无调用方则否
S472/73 · 75 行DRAW 诊断打印否（不移植）
S638/38 · 32 行进度条权重表否

6. 产品接口：完整 · 有效 · 可靠

审计关注「类是否存在」；状态画板关注「应用能否调用」。评审接口应优先看产品层。

产品入口底层路径完整有效可靠依据
开槽 / 颈部MakeRevol是是体积增减方向对
通孔 / 盲孔MakeCylindricalHole是是与 OCCT 探针五入口对拍
凸台MakePrism是是体积 / 贯穿
加强肋MakeLinearForm是是草图约定 + rib 检查
拔模DraftAngle是是Direction=中性面法向
通用布尔algo 门面是是与 Form 同路径

使用契约（可靠的前提）

  • 拔模方向取中性面法向，不是面法向
  • 肋使用 OCCT 草图线约定，不是旧板料三参
  • 部分 tol 仅为签名兼容，不驱动布尔 fuzzy
  • 失败返回错误，可带状态名

类已落、产品未包

  • MakeDPrism / MakePipe / MakeRevolutionForm
  • RibSlot 边表查询未回填到产品 API
  • 有真实几何约定后再加一键入口
  • 不等于算法没移植

8. 本轮与近几轮推进故事

2026-11-12（本轮）· 非 S7 产品缺口收口 肋改走线性成型；拔模改走官方 DraftAngle（方向=中性面法向）；布尔收尾 SimplifyResult 接线； 裁剪曲线真正 Reverse。门禁：编译通过 + 特征 17/17。故意不搬：调试转储、进度表、DRAW 诊断。

上一轮值得记住的技术故事（白话）

圆柱被另一个圆柱贯穿时，曾出现「根本没切 → 切了但不互相裁 → 多出一层闭合壳」三段读数。 团队沿官方源码逐层定位：连通块与走线、周期面参数曲线整周期重定位、面集合判等语义 （朝向是否参与比较）。最终收敛到与 OCCT 同面数、体量差约 3×10⁻⁴ 量级——这是忠实度审计的典型工作方式。
